# Запуск на Bothost (bothost.ru)

Репозиторий устроен так, чтобы Bothost собирал и запускал бота без ручных команд:
весь код лежит **в корне**, рядом `requirements.txt`, `bothost.json` и `main.py`.

```
main.py              ← главный файл (точка входа)
requirements.txt     ← обязательные зависимости
requirements-tls.txt ← необязательный TLS-бэкенд (curl_cffi)
bothost.json         ← подсказка платформе: язык и главный файл
PlayerokAPI/ Utils/ tg_bot/ locales/ configs/ scripts/
```

## Что настроить в панели

| Параметр | Значение |
| --- | --- |
| Язык | Python (версия 3.12; 3.11 тоже подойдёт) |
| Главный файл | `main.py` |
| Репозиторий | `klekotov/wet3456234er`, ветка `main` |
| Деплой | «Обновить из Git» (или загрузка ZIP — см. ниже) |

Версию Python можно не указывать вручную — она берётся из `bothost.json`.

## Переменные окружения

Bothost сам передаёт `BOT_TOKEN` и `DATA_DIR`. Нужно добавить только токен Playerok
и пароль для входа в Telegram-бота:

| Переменная | Обязательно | Что это |
| --- | --- | --- |
| `POC_PLAYEROK_TOKEN` | да | токен аккаунта Playerok (из Cookie, ключ `token`) |
| `POC_PASSWORD` | рекомендуется | пароль для входа в Telegram-бота (8+ символов, заглавные/строчные/цифра) |
| `BOT_TOKEN` | да (передаёт Bothost) | токен Telegram-бота от @BotFather |
| `POC_USER_AGENT` | нет | User-Agent браузера |
| `POC_HTTP_BACKEND` | нет | `auto` (по умолчанию), `curl_cffi` или `requests` |

Если `POC_PASSWORD` не задан, бот сгенерирует пароль сам и напечатает его в логе
работы — задайте переменную, чтобы пароль не менялся при следующем старте.

Конфиг `configs/_main.cfg` создаётся автоматически из этих переменных при первом
запуске, если файла ещё нет. В git он **не хранится** (репозиторий публичный).

## Сохранение данных между пересборками

Код живёт в `/app` и перезаписывается при каждом деплое. Изменяемые данные
(`configs`, `storage`, `plugins`, `logs`) автоматически переносятся в `DATA_DIR`
(`/app/data`) и подключаются символическими ссылками. В `/app/data` сохраняются:

* `configs/_main.cfg` — настройки и токены;
* `storage/products/*.txt` — товары для автовыдачи;
* `storage/cache/*` — кэш, чёрный список;
* `plugins/*.py` — плагины;
* `logs/*.log` — логи.

Если вы раньше запускали бота со старой структурой (код в `PlayerokCardinal-1.1.9/`),
перед первым деплоем новой версии скопируйте данные в постоянный каталог —
иначе при пересборке они пропадут. В терминале дашборда по одной команде:

```
cp -r /app/configs /app/data/configs
```

```
cp -r /app/storage /app/data/storage
```

```
cp -r /app/plugins /app/data/plugins
```

Если какого-то каталога нет (например, `plugins`), команда просто вернёт ошибку —
это нормально, пропустите её.

## Проверка после деплоя

В терминале дашборда:

```
python scripts/check_env.py
```

Скрипт покажет версию Python, установленные пакеты, выбранный HTTP-бэкенд и
импорт модулей проекта. Если всё в порядке — в конце будет «Всё в порядке».

## Типичные ошибки

**`ModuleNotFoundError: No module named '...'`**
Пакета нет в `requirements.txt` в корне — рестарт контейнера зависимости не
доустанавливает, нужен новый деплой (сборка образа).

**`can't open file '/app/PlayerokCardinal-1.1.9/main.py'`**
В настройках бота остался старый путь. Укажите главный файл `main.py`.

**`Не найден файл конфигурации configs/_main.cfg`**
Не заданы `POC_PLAYEROK_TOKEN` / `BOT_TOKEN` (или не перенесены данные в
`/app/data/configs`). Добавьте переменные и перезапустите бота.

**`curl_cffi` не устанавливается**
Это необязательный пакет: бот запустится на резервном бэкенде `requests`,
в логе будет предупреждение.

## Деплой из архива (вместо Git)

1. Профиль → «Интерфейс» → включить «Загрузка бота из архива».
2. Мои боты → «Загрузить из архива».
3. Загрузить ZIP с содержимым **корня** репозитория, главный файл — `main.py`.
4. Сохраняются те же переменные, домен и данные в `/app/data`.
